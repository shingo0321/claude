# 01. スケジュール管理・EVM

## 頻出の観点

- クリティカルパスの特定、遅延の波及、フロートの使い方
- 遅延回復策: **ファストトラッキング**(並行化)と**クラッシング**(資源追加)の違い
- 進捗の把握方法(進捗率の定義、完了基準の曖昧さ)
- EVMによる状況判断と予測

## EVMの用語と式

| 用語 | 意味 | 式 |
|---|---|---|
| PV | 計画価値(予定通りなら今ごろ終わっている作業の予算) | |
| EV | 出来高(実際に終わった作業の予算) | |
| AC | 実コスト | |
| SV | スケジュール差異 | EV − PV |
| CV | コスト差異 | EV − AC |
| SPI | スケジュール効率 | EV ÷ PV |
| CPI | コスト効率 | EV ÷ AC |
| EAC | 完成時総コスト予測 | BAC ÷ CPI(今の効率が続く場合) |
| ETC | 残作業コスト | EAC − AC |

- SV・CVが負、SPI・CPIが1未満なら遅れ・超過。
- **BACを今の予算どおりに完了できる前提なら EAC = AC + (BAC − EV)**(差異が一時的な場合)。どちらの前提かは問題文で確認する。

## 解答の型

- 遅延の原因: 見積前提の誤り、依存関係の見落とし、手戻り、資源の競合、完了基準の曖昧さ
- 対策: 該当作業へ資源追加(クラッシング)、並行化(ファストトラッキング)、スコープ調整、完了基準の明確化、進捗報告の粒度見直し
- **クラッシングはコスト増、ファストトラッキングは手戻りリスク増**、とトレードオフを一言添える。

## 見落としやすい点

- 進捗率「ほぼ完了」の自己申告に頼らず、成果物の完了基準で判断する。
- 遅れた作業がクリティカルパス上かどうかをまず確認する(フロートがあれば全体納期には影響しない)。
