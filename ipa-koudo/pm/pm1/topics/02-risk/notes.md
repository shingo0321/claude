# 02. リスク管理

## プロセス

リスクの特定 → 分析(発生確率×影響度) → 対応策の計画 → 監視・コントロール。リスクは**登録簿**で管理し、定期的に見直す。

## 対応戦略

| 脅威への対応 | 内容 | 例 |
|---|---|---|
| 回避 | 原因を除く | 未経験技術の採用をやめる |
| 軽減 | 確率・影響を下げる | プロトタイプで事前検証する |
| 転嫁 | 第三者に移す | 保険、契約による責任分担 |
| 受容 | 対応せず許容(予備費・コンティンジェンシー) | 影響が小さい |

好機(機会)に対しては、活用・共有・強化・受容。

## 頻出の観点

- **トリガ(予兆)の設定**: 「〜になったら対応策を発動する」と条件を決めておく
- コンティンジェンシー予備(既知のリスク用)とマネジメント予備(未知用)の違い
- リスク発生後の対応: 影響範囲の確認 → 対応策の実行 → ステークホルダへの報告 → 計画の更新
- 外部要因(委託先の遅延、要員離脱)への備え

## 解答の型

- 「発生確率と影響度を評価して優先順位を付ける」
- 「発生時の対応策と、発動条件(トリガ)を事前に決め、関係者と合意しておく」
- 「リスク登録簿を更新し、定例会議で状況を確認する」

## 見落としやすい点

- 問題が**すでに発生している**(課題)のか、**これから起きうる**(リスク)のかを区別する。課題は対応計画ではなく、解決の実行を答える。
